# FSM Planner

FSM is a learning-based planner that uses different sample generation improvement strategies to learn a heuristic function for classical planning. The heuristic function is a neural network trained on pairs of states and cost-to-goal estimates generated by regression from the goal state. The short time for sampling, training, and testing allows FSM to be competitive on the classical track of the IPC. The time dedicated to each of the mentioned steps is 15, 10, and 5 minutes, respectively.

FSM planner is completely based on the paper [Understanding Sample Generation Strategies for Learning Heuristic Functions in Classical Planning](https://arxiv.org/abs/2211.13316) and a fork from [Neural Fast Downward](https://github.com/PatrickFerber/NeuralFastDownward), which in turn derives from [Fast Downward](https://github.com/aibasel/downward).

## Installation

### Local Installation

1. **Clone the repository**

   ```bash
   git clone <repository-url>
   cd planner20
   ```

2. **Create and activate a virtual environment**

   ```bash
   python3 -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install Python dependencies**

   ```bash
   pip install -r requirements.txt
   ```

   Or using `uv` (faster):

   ```bash
   pip install uv
   uv pip install .
   ```

4. **Build the planner**

   ```bash
   ./build.py release
   ```

   Build options:

   ```bash
   ./build.py                     # Build release (default) using all cores
   ./build.py -j4                 # Build release using 4 threads
   ./build.py debug               # Build debug configuration
   ./build.py --all               # Build all configurations
   ```

### Docker Installation

**Option 1: Pull from Docker Hub (Recommended)**

```bash
docker pull miyurus/ai-planner:aiplanner
```

**Option 2: Build locally**

```bash
docker build --platform linux/amd64 -t fsm-planner:latest .
```

## Usage

### Using Docker (Recommended)

**Option 1: Use the wrapper script**

```bash
./run-planner.sh <domain_file> <problem_file> <plan_file>
```

Example:

```bash
./run-planner.sh test_domain/airplane/domain.pddl test_domain/airplane/problem01.pddl plan.txt
```

**Option 2: Run Docker directly**

```bash
docker run --rm \
    -v "$(pwd)/your-domain.pddl:/app/domain.pddl:ro" \
    -v "$(pwd)/your-problem.pddl:/app/problem.pddl:ro" \
    -v "$(pwd):/app/output" \
    -v "$(pwd)/FSM.results:/app/FSM.results" \
    miyurus/ai-planner:aiplanner \
    /app/domain.pddl \
    /app/problem.pddl \
    /app/output/plan.txt
```

**Option 3: Using docker-compose**

```bash
docker-compose run planner
```

### Local Execution

```bash
python run.py <domain_file> <problem_file> <plan_file>
```

Example:

```bash
python run.py test_domain/blocksworld/domain.pddl test_domain/blocksworld/problem01.pddl plan.txt
```

**Using Fast Downward directly** (for advanced users):

```bash
python fast-downward.py test_domain/airplane/domain.pddl test_domain/airplane/problem01.pddl --search "astar(lmcut())"
```

## Test Domains

The `test_domain/` directory contains three classical planning domains for testing:

### 1. Airplane Domain (`test_domain/airplane/`)

Models air transportation logistics where airplanes transport passengers between cities.

| Difficulty | Problems | Description                            |
| ---------- | -------- | -------------------------------------- |
| Easy       | 01-05    | 2-3 cities, 1 airplane, 1-2 persons    |
| Medium     | 06-10    | 4-5 cities, 2 airplanes, 2-3 persons   |
| Hard       | 11-15    | 6-8 cities, 2-3 airplanes, 4-5 persons |

**Actions**: `fly`, `board`, `deplane`

### 2. Blocksworld Domain (`test_domain/blocksworld/`)

Classic blocks manipulation domain where blocks must be stacked in a specific order.

**15 problems** of varying complexity.

**Actions**: `pick-up`, `put-down`, `stack`, `unstack`

### 3. Elevator Domain (`test_domain/elevator/`)

Models elevator operations for transporting passengers between floors.

**15 problems** of varying complexity.

**Actions**: `move-up`, `move-down`, `board`, `leave`

### Running Examples

```bash
# Airplane domain - easy problem
./run-planner.sh test_domain/airplane/domain.pddl test_domain/airplane/problem01.pddl output/airplane_plan.txt

# Blocksworld domain
./run-planner.sh test_domain/blocksworld/domain.pddl test_domain/blocksworld/problem05.pddl output/blocks_plan.txt

# Elevator domain
./run-planner.sh test_domain/elevator/domain.pddl test_domain/elevator/problem03.pddl output/elevator_plan.txt
```

## Project Structure

```
planner20/
├── driver/                 # Python driver for Fast Downward
├── src/
│   ├── pytorch/           # Neural network training modules
│   ├── search/            # C++ search algorithms
│   └── translate/         # PDDL translator
├── test_domain/           # Test planning domains
│   ├── airplane/
│   ├── blocksworld/
│   └── elevator/

├── FSM.results/           # Output results directory

├── build.py               # Build script

```
